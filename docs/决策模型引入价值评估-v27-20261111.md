# 决策模型（判官）引入价值评估 — v27 · 2026-11-11

> 背景：小蜜蜂实测「决策模型直接用 llama 部署访问有问题，需要另外的组件」。
> 本文回答唯一一个问题：**引入决策模型是否真正能优化聊天/任务质量？值不值得现在投时间？**
> 口径：全部结论来自 dev 台账实测 + 代码事实，**本轮 0 行代码改动**。

---

## 0. 结论先行

1. **接不进去是真的，而且不是 llama 的错，是预算的错。** 判官真判实测 **均值 6.3 秒 / 峰值 17 秒**；主链软阈值 **2000ms**、本地链路硬熔断 **15000ms**。12~18 秒的本地模型 **必然超时**，超时即弃权 → 主链照常放行 → **判了等于没判**。换组件只能解决「能不能连」，解决不了「来不及」。

2. **价值层比时延层更致命：判官现在几乎没有区分度。** 验收岗真判 21 行里 **17 行判 satisfied（81%）**，partial 2、failed 2。一个 81% 全票通过的裁判，对质量的净贡献趋近 0。

3. **下游闭环基本没跑。** 台账 `outcome`：**pending 300 行 / hit 8 / miss 2** —— 96.8% 的判决没有任何回执。判官说了什么，系统事后不认、不改、不追。

4. **判断：现在不要为决策模型投时间。** 建议判官保持「槽位空 = 安全弃权放行」（四层降级已保证不会因此坏），转「离线评测 + 事后审计」；把时间花在 4 件确定性收益的事上（见 §5）。设 go/no-go 门槛（§6），达标再上在线。

## 2. 「接不进去」的技术真相

| 现象 | 根因 |
|---|---|
| llama.cpp 直连的 StartLux-4B 当判官不可用 | ① 时延 5~17s ≫ 主链 2s 软阈值 → 必超时弃权；② 峰值 > 15s 硬熔断 → 补判也被砍；③ llama.cpp 的 OpenAI 兼容层非完整 Chat Completions 语义（v18 §5.5 实测：`/v1/systemone` 返回 501 非 404，模型 `output_modalities=[text]`，思考/流式/工具语义与判官链所需不一致） |
| 「需要另外的组件」 | 判官链要的是**低时延、稳定 JSON、可关思考、可 2s 内返回**的服务。llama.cpp 单请求串行 + 4B 模型生成速度决定了它不适合在线；要在线必须换 vLLM/Ollama（连续批处理、并发）或用远端 API（预算 5000ms） |
| 代码侧缺口（不是小蜜蜂的错） | 判官实现在 `gateway.py:989` 走 **chat completions**；v18 设计的 SystemOne（`/v1/systemone`）全仓 grep **0 处实现** —— 契约未落地 |

**换组件能解决什么**：能让判官「连上、跑起来」。
**换组件不能解决什么**：判得准不准（无标注集）、判了有没有用（outcome 闭环 96.8% 空）、一期不拦截（工具闸只注入 HINT 影响**下一个**动作，`react_agent.py:3960/3997`）。

## 3. 逐岗位「效果上限」矩阵（判官若全速可用，最多能改变什么）

| 岗位 | 判官结论 | 实际动作 | 对**本次交付质量**的影响 | 上限评级 |
|---|---|---|---|---|
| plan_gate 判档 | 档位 + effort | 决定主模型思考开支 | 简单任务关思考省时；复杂任务开思考提质 | **中**（唯一有真杠杆的岗） |
| skill_trigger 技能触发 | 命中/不命中 | 注入哪些技能进上下文 | 上下文质量 | 低-中（实测 85/94 行无命中） |
| tool_gate 工具闸 | allow / reroute | **只注入 HINT，不改本次执行**（一期不拦截，block 一律降级 reroute） | 影响**下一个**动作 | 低 |
| advisor 事中改道 | continue / change / stop | 发射即忘 + 注入提示 | 影响后续动作 | 低 |
| acceptance 验收 | satisfied/partial/failed | 回填 outcome → 下一轮加严 | 不改本次；驱动自校准 | 低（81% 全票 satisfied） |
| plan_review 计划复核 | 加严/改道 | 计划阶段提示 | 计划质量 | 低-中（近 7 天仅 3 行） |

一句话：**在线五岗没有一个能硬拦**，全是「提示注入」级软干预；唯一真杠杆是判档→思考开支，而它只需要**消歧 medium 带**。

## 5. 建议路线（不投决策模型，先吃确定性收益）

**A. 判官现状冻结**（0 成本，0 风险）
槽位保持空 = 弃权放行；四层降级 + 熔断已验证不会因缺模型而坏。台账/看板继续跑 = 免费的决策可观测性。

**B. 把「护栏」从模型手里拿回来，用规则做**（确定性、零时延、零部署）
现在规则层只有 **2 条规则**（`hub_tool_gate.py`）：① 同工具同参数连续第 3 次=原地打转；② 无明确目标就动破坏性动作。
可扩充的确定性规则（都不需要模型）：
1. 破坏性命令分级（`rm`/`DROP`/`git push -f`/写系统路径/改部署）→ 直接要求确认
2. 重复失败熔断（同一目标连续 N 次失败→强制换路）
3. 越界写检测（写工作区外、写 `.env`/compose/密钥）
4. 预算护栏：步数/时间/token 上限 + 超限自检
5. 空转检测（连续只读不改→提示收敛）
台账实测支撑：tool_gate 26 行 rule 直判 vs 38 行 no_model —— 规则层明显没吃饱，**这是判官岗位上最便宜的替代**。

**C. 验收改「自检验收」**（零部署）
主模型按判则 checklist 自评（交付物/边界/过度设计三条红线），结论进台账。省掉一次 9 秒的外部判断，把「81% 全票 satisfied」的假绿换成带证据的自检。

**D. 判官转离线评测**（这才是决策模型的正确用法）
用已有评测体系跑批量样本：同一批任务，规则判档 vs 模型判档 vs 人工标注，出三个数——
- 规则与人工的分歧率（= 判官的价值上限）
- 模型判官与人工的一致率（= 判官的真实能力）
- 验收 verdict 区分度（satisfied 占比）
**零在线风险、零时延、零部署**，一周内能拿到「要不要上」的答案。

## 6. Go / No-Go 门槛（数据说话，避免再凭感觉投 6 人日）

三条**同时**达标才接在线消费点；任一不达标 → 判官停在「离线评测 + 事后审计」。

| 门槛 | 指标 | 达标线 | 现状 |
|---|---|---|---|
| 判准率 | 与人工标注一致率（≥100 样本） | **≥ 70%** | 未测（无标注集） |
| 格式合法率 | 判官输出可解析为契约 JSON | **≥ 95%** | 历史 17%（小模型） |
| 在线时延 | 真判 p50 | **≤ 1 500 ms** | 实测均值 5.6~11.4s ❌ |
| 区分度 | 验收 satisfied 占比 | **≤ 70%** | 81% ❌ |
| 闭环 | outcome 非 pending 占比 | **≥ 50%** | 3.2% ❌ |

现状：**5 条里 3 条明确不达标，2 条未测**。这就是「先不要花太多时间」的量化依据。

## 7. 如果小蜜蜂坚持要接（最省的路）

1. **别为在线接本地 4B**：在线只用远端 API 小模型（预算 5000ms 内，p50 需 <1.5s）。
2. **本地模型只喂离线评测/审计**：llama.cpp 慢没关系，离线没人等。
3. **在线只接 1 个岗位**：判档岗（唯一真杠杆，且只需消歧 medium 带），其余岗位先规则化。
4. **验收岗留本地慢模型**（软 12s / 硬 20s，幕后，不挡人）。
5. 先补 D1~D3 标注实验，判准率 ≥70% 再谈接线。

### D3 — 自检验收（`decision/selfcheck.py`，新模块）

判官槽位空时验收回填链整条停摆（台账 outcome 全票 pending 的成因）。补一条**不依赖判官**
的路：轮尾用本轮会话模型按**同一张验收判则**（`rubric_for('acceptance')`、同一个 JSON
形状）自评，只做两件事——写 `source=selfcheck` 台账行、走同一条 `_backfill_plan_gate`
回填档位（必须 await：取协程不 await 等于没回填）。

边界写死在模块 docstring：**不拦动作、不加动作、不改回答、判官在岗时不抢话、不进主链
（超时即弃）**。自评连建议权都没有——让考生给自己打分再据此改道，等于把考官换成考生本人。
台账单列 `selfcheck` 来源（`ledger_contract.SOURCES` 扩充），前端筛选单列一项，就是要把

配置三把尺子（`COAPIS_DECISION_SELFCHECK_*`）：`selfcheck_enabled`（默认开）、
`selfcheck_timeout_ms`（默认 20000，夹取 2s~60s）、`selfcheck_min_answer_chars`（默认 80，
短交付不自评，免出垃圾行）。
