## 2. 一句话方案：文件不动，索引集中，入口唯一

你担心的「文件分散、集中不了、找不到」，**不要用物理搬迁解决**，因为：

- 技能靠目录加载（`coapis/agent/skills/` 是运行时扫描目录），搬走即全部失效；
- 工作区文件挂着台账、预览、下载三条链路；
- 企业版上传文件挂着知识库绑定关系。

搬一次 = 三条链路全断 + 全量迁移风险，收益为零。

**正确解法：三层分离，只集中"索引和界面"，不动"文件本体"。**

```
真相源层（文件，原地不动）      索引层（集中一份，可重建）        界面层（唯一入口）
─────────────────────       ─────────────────────         ─────────────
知识条目 .json  …… 注册表一行记录 ←───────── 「知识台」页面
技能 SKILL.md   …… 注册表一行记录              4 个分区
工作区产物      …… 注册表一行记录              1 个搜索框
（企业版上传资料 … 注册表一行记录）             0 个路径要认
```

- 文件留在原处 → 零迁移、零破坏；
- 注册表 = 一处集中登记的清单，每行记「是什么、哪来的、存在哪、被用过几次、价值多高」；
- 界面只读注册表 → **不懂技术的人只面对一个页面，永远不需要知道任何路径**。

这与社区版已有的台账是同一个套路（台账早就在做「文件在原地、信息集中登记、读取去重」），不新造机制。

## 4. 存储：一条知识怎么产生（全自动，写路径时序）

**全自动入档 = 挂在"回复结束"这个现成钩子上，用户零操作。**

```
用户提问 → 智能体回答 → 回复结束钩子 post_reply
                              ↓ （异步，不阻塞回复，失败只记日志）
                        ① 取本轮新增记忆条目（memories 表按会话取）
                        ② 取本轮台账新记录（resources / file_records）
                        ③ 逐条过「入档判据」打分
                              ├ 不达标 → 丢弃（不留痕，避免垃圾堆积）
                              └ 达标 → ④ 去重：与同类别现有条目标题做 text_similarity
                                          ├ ≥0.85 → 合并：hits+1、priority 上调，不新增
                                          └ <0.85 → 新增
                                        ⑤ 落 json 文件（_save_to_knowledge_base）
                                        ⑥ 注册表登记一行（kind=learned，scope 按规则）
                                        ⑦ 配额检查（can_add）→ 满则触发自动淘汰
```

作用域自动判定（不让人选）：
- 来源会话绑定场景 → 该场景共享知识 `scope=shared`；
- 与个人偏好/个人数据相关 → `scope=private` + `owner_user`；
- 其余 → `shared`。

**入档判据（防垃圾，全自动必须有的闸门）** —— 四条同时满足才入档：
1. **有结论**：含明确的「做法定论/参数/事实」，不是过程叙述；
2. **可复用**：不是一次性参数（文件名、临时路径、本次任务编号一律不入）；
3. **有出处**：能给出来源会话号；
4. **不重复**：与已有条目相似度 < 0.85（`text_similarity` 现成）。

打分用社区版已有的判官中枢（判官模型 + `decision_events` 留痕），**判官不可用时降级为规则判定**（关键词+长度+排除表），绝不因判官失败而阻塞会话。

### 检索与注入（读路径）

- 关键词检索 `search_knowledge` 已有，社区版**不引入向量库**：用「关键词 + 标题相似度 + 时间衰减 + 命中加权」排序，`priority = f(命中次数, 最近使用, 判官分)`。
- 注入继续走现成的 `build_initial_context` / `build_incremental_context`，注入条数与 token 由现成配额（`memory_quota.py`）卡死，不撑爆上下文。

## 5. 管理：一个页面解决「找不到」

### 5.1 知识台（社区版新页面，替换空壳）

- 菜单项「知识库」路径从 `/ent/knowledge-bases` 改为 **`/knowledge`**（社区版自己的路由，不再指向企业版 → 消灭必 404）。
- 权限沿用现有 `knowledge:read`（菜单已写死用它，社区版权限表补这项）。
- 页面结构（默认极简，按需展开 —— 遵循分层暴露规范）：

```
知识台
┌────────────────────────────────────────┐
│ 搜索框：一句话问它「你知道怎么…」        │ ← 默认就这一屏
├────────────────────────────────────────┤
│ 学到的 (128)  产出的 (340)  技能 (36+7) │ ← 三个分区标签
├────────────────────────────────────────┤
│ 卡片列表：中文标题 / 一句话摘要 / 来源   │
│          「这条有用」「这条别记了」      │
└────────────────────────────────────────┘
展开详情才显示：分类、来源会话号、文件位置
```

- 用户只需要三个动作：**搜、看、点「这条别记了」**。零路径、零术语。
- 「这条别记了」→ 注册表 `status=archived` + priority 清零 + 记一次负反馈（同类判据阈值上调）。这是全自动唯一的人工兜底，一键、不阻塞。

### 5.2 自动淘汰（拍板②落地）

规则（全部自动，写进配置，可调）：

| 条件 | 动作 |
|---|---|
| 配额满（`can_add` 为假） | 触发淘汰，腾位给新知识 |
| 命中 0 且创建超 90 天 且 priority 最低 | 归档：json 文件移入 `_archive/{category}/`，注册表 `status=archived` |
| 被用户标记「别记了」 | 立即归档 |
| 归档条目满 180 天 | 物理删除（`trash` 优先，不直接 rm） |

**关键约束：淘汰默认只归档，不物理删除**（现成 `_evict_lowest_priority` 是直接删文件的，需改为归档优先）。理由：全自动入档必然产生错档，归档可回滚，物理删除不可。

### 5.3 与"用户知识库"的区分（拍板点，社区版侧）

| | 知识台（本次新建） | 用户知识库（企业版功能） |
|---|---|---|
| 内容 | 系统从会话里**自己学到**的 | 用户**自己上传**的资料 |
| 谁写 | 系统自动 | 用户主动上传 |
| 规模 | 小而精（配额卡死，百条级） | 大而全（万级文件） |
| 存储 | json 文件 + 注册表 | 企业版 uploads + Weaviate 向量 |
| 界面 | 「知识台」 | 「资料库」 |
| 社区版 | ✅ 有 | ❌ 无（前端空壳页要收走） |

两条线**数据不混、界面分开、检索分开**。聊天时是两个开关：勾「资料库」走向量检索；「知识台」的知识自动注入，不用勾。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 全自动入档产生垃圾知识 | 四条判据 + 判官打分 + 相似度去重 + 配额硬上限 + 一键「别记了」负反馈 |

| 空壳页收走影响企业版 | 企业版有自己的页面（`coapis-pro/client/src/pages/KnowledgeBase*`），社区版空壳与其无关 |

3. **归档保留期**：建议 180 天后物理删除，`trash` 优先。
