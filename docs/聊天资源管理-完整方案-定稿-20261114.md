## 3. 完整方案（推荐设计）

原则：**纯前端、纯社区版**；不新增后端接口；不复活右栏；不改历史数据；不动范围切换结论。

### 3.1 行渲染收敛为一套行（1.5 人日）

新增 `pages/Chat/components/ChatResourceRow.tsx` 作为唯一行实现：

```
ChatResourceRow({ item, variant: "chat" | "session", onPreview, onLocate?, onDelete?, onDownload? })
```

- 行内结构固定顺序：类别图标 → 文件名 → 大小/版本/更新时间 → 来源标签 → 操作区
- 图标与来源继续走 `resourceDisplay.tsx`（`categoryIconOf` / `sourceOf` / `SOURCE_LABEL_KEY`），不改口径
- `variant` 只影响两件事：密度（chat 单行可横向滚动、session 紧凑换行）与操作集合（session 多删除/下载）
- 抽屉表格保留表格骨架，但"名称+图标+来源"单元格内渲染改用同一子组件，避免第三套行
- 作用域边界写进数据层调用处，不靠 UI 猜：聊天 `scope=chat` + 本轮过滤；左栏 `scope=session`；抽屉 `scope=chat`
  —— 三处都经 `getChatResourcesShared`，天然只发一次请求

配套：三份行样式合并为 `ChatResourceRow.module.css`，外层容器样式各自保留（左栏 240px 窄栏、
抽屉表格、气泡末尾条属于布局壳，不强行统一，降低视觉回归风险）。

### 3.2 文案接实（0.3 人日）

- 7 项文案接上使用点：来源=「其他」标签、空态四套（加载中 / 失败可重试 / 无资源 / 筛选无结果）
- 左栏 Inline 现有四态是硬编码中文 → 改走 i18n key，四语言同步
- 与 3.1 同文件，必须同轮改，禁止先删文案再补

### 3.3 契约测试补齐（0.7 人日）

| 测试 | 断言 |
|---|---|
| 左栏整会话口径 | 会话含 3 聊天、各 2 资源 → 渲染 6 行；切换会话不出现上一会话数据；来源四类各有行 |
| 抽屉当前聊天口径 | 行数只等于当前聊天；不出现跨聊天行；删除后计数 -1；搜索/分页作用域不变 |
| 行组件变体矩阵 | chat/session 两变体的操作集合差异；图标与来源标签必现；空值不渲染图标 |

现有三份测试不得回归。

### 3.4 浏览器实测走查（0.5 人日）

Chrome，1440 / 1180 / 900 / 760 四档宽度，逐条留证：
上传、生成、知识库引用、引用原文预览、左栏切会话与展开、抽屉打开/搜索/分页/删除/定位、
浮窗拖拽与最小化、输入框退格不被快捷键劫持、消息区独立滚动。

### 3.5 明确不做（防再被提出）

- 右栏常驻列复活 —— 左栏（整会话）+ 抽屉（全量表格）+ 预览窗已覆盖，重开必带回遮挡与双滚动条

- 写入渠道列 —— 已拍板不做
- 新增"右栏入口"按钮 —— 入口已在（查看全部 / 预览）
- 后端与企业版任何改动 —— 台账与预览端点已够用
- 历史数据迁移与回填 —— 不动
