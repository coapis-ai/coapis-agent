**2.2 关键路径现状（v12 低估处，修订）**

v12 说"一处同步调用最坏 5 秒"。实测：该调用位于聊天主流程生成之前，**每次执行新建单线程线程池 + 线程内起独立事件循环 + 同步等待 5 秒**；且只在关键词全部落空时才触发——即"新任务、新表述"这一最典型场景。**修订为：关键路径存在结构性反模式（线程池 + 嵌套事件循环），必须一并清除，不只是改超时。**

**2.3 安全边界：「只加严不放宽」有现成机制**

工具防护统一引擎已有「严重度下限抬升」（极严重→拦截、高→需人工确认）与动作合并语义。**新增必须定义的优先级**：该引擎同时存在**降级规则会放宽动作**——v13 规定「判据只抬升，降级规则只对硬规则生效」（决策点 D6）。

### P1 入口路由 —— 输入面扩展（重点①③）

| 历史上下文 | ✅ 现成（四层记忆注入 + 配额） | 复用，注意 U4 |

### P2 计划审查 → **计划审查 + 事中判级**（重点②）

- **事前**：判据输入**强制包含附件解析步骤存在性**——有附件未安排解析，直接判"计划落空"（D4）。
  系统已有计划判级器并接入执行链（含轻量判级），**P2 是改造它，不是新建**。
- **事中（新增）**：计划步骤状态机已存在（待办/进行中/已完成/已放弃）且每轮被消费。
  在**步骤状态迁移处**插判级：输入 = 已完成步骤产出 + 剩余步骤 + 已用预算；输出 = 继续 / 改道 / 升级模型 / 请求确认；结论写台账。
  范围：只对关键步骤复判（D3）。
- 挂载点：工具调用前/后钩子（框架已有 8 阶段，含 PRE_ACT / POST_ACT）。

### P3 执行闸门

- 挂工具防护统一引擎，复用其「严重度下限抬升 + 动作合并」的只加严语义。
- **必须先定义**与降级规则的优先级（见 2.3 / D6）。
- 输入补：操作者角色 + 目标资源归属（本会话 / 他人会话 / 系统目录）。

### P4 完成验收

- 系统已有大模型裁判 + 判据检查器（通过/部分/不通过 + 理由），**已接入在线采集**。P4 复用，不新造裁判。
- 挂载会话收尾钩子（已有）；"声明完成后追加补充消息"复用计划广播通道（已有）。
- **新增判据**：附件解析失败不得判"已完成"（验收标准第 8 条）。

### P5 技能与知识库优选 —— 根因修正（重点①）

v12 把它当策略问题。核实是**两处实现缺陷**：

1. 技能选择器在异步上下文**直接返回空**，注释断言"聊天流程里不会发生"——而聊天主流程就是异步 → **大模型技能选择在正常聊天中从不执行**。
2. 聊天主流程兜底只在关键词全部落空时启用，且用线程池 + 嵌套事件循环**同步阻塞 5 秒**。

→ 修这两处（第 0 批）收益大于新建整套机制。
→ **知识库侧延后单列一批**：前端知识库页面已在调用检索接口，**后端无对应路由、检索服务不存在**（风险表新增第 8 条）。

### P6 成本与模型分层

- 建在现成配额体系之上。
- 本地量化判别模型可行性**已实测确认**：本机四卡共 90GB 显存，第一张全空 22.5GB，且本机已有量化模型常驻运行先例 → 3GB 级判别模型可共存。

## 12. 【新增章】第 14 章 · 聊天信息面优化（用户信息提示 + 上传文件）

> 这一章是判断中枢的**数据地基**：输入面不补齐，P1/P2/P3/P4 就没有判据可判。
> 对应小蜜蜂点名第三件事：「注意聊天中优化用户信息提示、用户上传文件」。

### 14.1 现状（核实）

**系统提示词构成**：身份文件（AGENTS/SOUL/PROFILE）+ 环境上下文 + 场景提示词。
**环境上下文内容**：会话标识、用户 ID、渠道、工作目录、当前时间（用户时区）、提示语。
**记忆注入四层**：用户记忆 / 用户画像 / 智能体记忆 / 场景共享经验，带配额。

**上传链路已实现（比 v12 预期好）**：
上传带会话标识 · 10MB 上限 · **重复上传判重并友好提示** · **上传前按模型能力校验图片/视频** · 拖拽上传 · 上传即登记台账 · 文件引用解析为绝对路径后注入提示词。

### 14.2 用户信息提示缺口 U1-U4

| # | 缺口 | 影响 | 修法 |
|---|---|---|---|
| **U1** | 环境上下文只注入用户 ID，**无用户名、角色、权限等级** | 判断中枢无法按"谁在说话"判风险；权限判断只存在于护栏硬规则 | 环境上下文增注入用户名/角色/权限等级；作为 P1、P3 输入（D10） |
| **U2** | 时区取**全局配置**而非按用户 | 多用户下时间提示必错 | 时区按用户取，全局值仅作兜底 |
| **U3** | 用户画像是自由文本，无结构化角色/部门/权限 | 判据无法稳定引用 | 画像增结构化字段，文本保留 |
| **U4** | 场景共享经验在配额紧张时**最先被丢弃** | 越需要场景经验的任务越先丢，与 P5 优选冲突 | 丢弃顺序改为按本轮任务相关性 |

### 14.3 上传文件缺口 A1-A6

| # | 缺口 | 修法 |
|---|---|---|
| **A1** | **解析结果不入台账**——解析器返回结构化结果（成功/内容/字符数/格式）但不落库，"解析状态"根本没被持久化 | 解析结果写台账（成功/失败/超时/超阈值/降级方式），成为 P1、P2 强制输入。**P1/P2 的前置依赖** |
| **A2** | 无粘贴上传 | 支持粘贴图片/文本文件 |
| **A3** | 拖拽无视觉反馈（只阻止默认行为，无拖入提示态） | 增拖拽态视觉提示 |
| **A4** | 进度是**假进度**（回调直接返回 100%） | 大文件走真实进度，或明确显示"上传中"不显示百分比 |
| **A5** | 附件与判断脱钩：有附件不告诉计划审查 | 附件清单 + 解析状态进 P1 输入、P2 强制判据 |
| **A6** | 上传成功仅提示"已上传到工作区"，未告知"已归入本会话 / 已入台账 / 第几版" | 提示语补会话归属与版本，与台账一致 |

> **勘误说明**：上一轮核实报告曾把"拖拽上传、上传进度、重复识别"列为缺失，经取证更正——**三项均已实现**，真实缺口为"拖拽无视觉反馈、进度为假、重复识别已有但文案不告知台账归属"。详见核实报告 8.1。

### 14.4 与判断中枢的接线

- **P1 输入面** = 任务文本 + 附件清单（含解析状态）+ 用户上下文（含角色权限）+ 模型能力 + 配额余量
- **P2 强制判据** = 有附件必有解析步骤；有权限边界必有确认步骤
- **P3 判据输入** = 操作者角色 + 目标资源归属（本会话 / 他人会话 / 系统目录）
- **P4 验收输入** = 附件解析是否成功（解析失败不得判"已完成"）

### 14.5 本章验收标准

1. 环境上下文含用户名/角色/权限等级，且随用户变化。
2. 时区随用户变化（多用户对照实测）。
3. 上传任一文档后，台账可查到该文件的解析状态与降级方式。
4. 上传 pptx/docx 而计划无解析步骤 → 必被判"计划落空"并留痕。
5. 附件解析失败的任务不被判"已完成"。
6. 上传成功提示含会话归属与版本。
