## 0. 一句话摘要

聊天页右侧那条 200px「会话资源/聊天资源」栏与左栏当前会话行的下拉菜单**接口相同、作用域相同、缓存相同**——生产实测 153 个聊天对 150 个会话，右栏上下两区**98% 显示同一份数据**，属纯冗余；而它常驻占位已实打实挤掉 200px 对话区，并逼出一个 44 行的窄屏补丁。

本版定稿：**右栏整列下线、跨聊天汇总彻底不做、左栏当前会话行的资源下拉改为默认展开**。净删 1256 行、新增 22 行。后端**零改动**，企业版**零改动**。

实施后首屏的常驻资源入口从"右栏 200px 常驻（与左栏重复）"变成"左栏当前会话行展开的资源面板（260px 宽、限高 168px）"，重复消除、宽度收回。

## 2. 现状实证（保留 v1 全部证据）

### 2.1 关键发现：右栏上下两区是**同一个接口、同一个作用域**

读源码 `components/ChatResourceRail/index.tsx:61-79`：右栏分上下两个分区，**都调用同一个 `listChatResources(chatId)`**——同一个后端端点、同一个参数：

| 右栏分区 | 标称含义 | 调用参数 | 请求数上限 | 实际作用域 |
|---|---|---|---|---|
| 上「会话资源」 | 跨聊天汇总 | `chatId = getSessionIdForChat(chatId)` | 200 | **当前聊天** |
| 下「聊天资源」 | 当前聊天 | `chatId = 当前 chatId` | 40 | **当前聊天** |

`getSessionIdForChat`（`sessionApi/registry.ts:242`）只做前端会话 id → 后端聊天 id 的翻译，返回的就是聊天自己。台账写入侧（`foundation/file_ledger.py:198,212`）登记的 `chat_id` 也是聊天 id，**系统里没有任何一处把多个聊天聚合到一个会话下**——聊天与页面会话是 1:1 的，会话层是空壳。

**生产实测（`coapis-enterprise` 容器 + 生产 PostgreSQL，已执行）**：

```
聊天数 = 153    会话数 = 150
会话资源返回数 vs 聊天资源返回数：一致 150 / 不一致 3  （一致率 98.04%）
会话资源恒为空的聊天：145 / 153
```

**结论：右栏上下两区显示的是同一批数据。** 左栏当前会话行的下拉菜单用的也是同一个端点。**右栏是纯冗余。**

### 2.2 关键发现：右栏常驻占位造成的挤压是实打实的

| 位置 | 尺寸 | 代码位置 |
|---|---|---|
| 右侧栏常驻宽度 | **200px** | `pages/Chat/index.module.less:49-50` |
| 对话区左内边距 | 80px → 16px | `index.module.less:199-201` |
| 窄屏补丁 | <1500px 时 200 → 56px | `index.module.less:493-502` |

200px 常驻挤压对话区，并逼出窄屏补丁。左栏常驻 260px（`ChatSessionSidebar/index.module.less:3`）不在此次讨论范围（它承载会话列表）。

### 2.3 关键发现：跨聊天汇总的能力**在代码里已不存在**

| 证据 | 位置 | 说明 |
|---|---|---|
| 资源浮窗的 `scope` 恒为聊天 | `CoApisResourceDrawer.tsx:44-48` | `scope="session"` 时标题叫「当前会话」 |
| **全仓库 `scope="session"` 零调用** | `CoApisResourceDrawer.tsx:181` | 打开浮窗只传 `scope: "chat"` |
| 台账服务有跨聊天方法但零调用 | `services/chat_resource_scope.py` | 已核实**零处调用** |

→ 本版按拍板②：**彻底不做跨聊天汇总**，这条死参数与死服务一并清理（见 4.3 / 4.4）。

### 2.4 关键发现：「产出卡」代码已下线，气泡条是其唯一存活入口

| 事实 | 位置 |
|---|---|
| 产出卡注册已被注释删除 | `pages/Chat/index.tsx:2386`（注释"已下线，由气泡内本轮资源条替代"） |

### 2.5 左栏资源下拉的现状（本版新增实证）

资源面板挂在"当前会话那一行"下方，由展开位 `expandedId` 控制（`ChatSessionDropdown/index.tsx:350-356`），caret 常驻当前会话行（`:117-119`，收起也在）。实测行为三态：

| 场景 | 现状 | 代码依据 |
|---|---|---|
| 首次进入页面（无历史记录） | **收起** | 惰性初值取 sessionStorage，无记录 → `null`（`:350-356`） |
| 刷新页面 | 恢复用户上次选择 | 展开位写入 sessionStorage，键 `coapis.chat.sidebarExpandedId`（`:371-372`） |
| 切换会话 | **自动展开到新会话** | 当前会话变化时展开位跟随（`:385-395`） |
| 同一会话内用户手动收起 | 不反弹（尊重用户） | 仅"会话真的换了"才跟随（`:383` 注释） |
| 点一行会话 | 展开该行；再点已展开那行则收起 | `:552-556` |

→ **拍板⑤要改的只有第一行**：首次进入页面时默认展开。其余四态现状已符合预期，**一行都不用动**。

### 2.6 左栏的容量口径（实测）

| 项 | 值 | 位置 |
|---|---|---|
| 左栏宽度 | 260px | `ChatSessionSidebar/index.module.less:3` |

### 4.3 左栏默认展开（拍板⑤·本版新增，约 20 行）

改动集中在 `ChatSessionDropdown/index.tsx` 三处，**其余展开位逻辑一律不动**：

| # | 位置 | 现状 | 改为 | 理由 |
|---|---|---|---|---|
| ① | `:350-356` 展开位惰性初值 | 读 sessionStorage，无记录 → `null`（收起） | 读 sessionStorage；**无记录 → 当前会话的后端 id**（默认展开） | 首次进入即展开。切换会话、刷新恢复、手动收起不反弹三态全部不变 |
| ② | `:371-372` 写入 | 展开写 id，收起 `removeItem` | 展开写 id；**收起写哨兵值 `"collapsed"`** | 现状收起后 `removeItem`，与"无记录"无法区分；若初值直接回落到当前会话，用户收起后一刷新又被撑开，**破坏既有语义**。加哨兵即可区分"从未设置"与"显式收起" |
| ③ | 跟随逻辑 `:385-395` | 会话变化时展开位跟随 | **不动** | 已实现"切换会话自动展开" |

**口径细则（三条，写进验收）**：

1. **默认展开只对当前会话生效**，其他会话行仍无资源面板（`showCaret` 只挂当前会话行，`:117-119`，不变）。
2. **用户显式收起即持久尊重**：收起 → 写哨兵 → 刷新后仍收起；再点开 → 写 id → 刷新后仍展开。
3. **无资源会话的表现**：展开位生效但面板无内容，现状渲染一行灰字「本会话暂无资源」（`Inline.tsx:214-216`）。**保留这一行**（改动 0 行）——它是"这个会话没有产出文件"的明确告知；若改成"无资源就不渲染面板"，需要把数量从面板层提升到列表层跨组件传递（约 +20 行 + 新增耦合），且 caret 点击后无内容可显示，**不划算，建议不做**（见 11.2 第 1 条）。

**新增副作用（必须写进验收，非阻断）**：

- 面板挂载时有一条"把面板滚进视野"的滚动逻辑（`Inline.tsx:112-118`，`scrollIntoView({block:"nearest"})`）。默认展开后首屏会触发一次；因当前会话通常排在列表首位，`nearest` 语义下元素已在视野内则不滚，**预计无感**。需在验收中实测确认首屏不被推走。
- 展开态占高约 280px（约 2.7 个会话行），左栏可见会话行数减少；面板限高 168px 内部滚动 + `overscroll-behavior: contain` 已保证滚到底不带滚整条左栏（`inline.module.less:19`）。
