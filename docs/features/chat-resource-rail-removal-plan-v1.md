# 聊天页右侧资源栏下线方案（拍板落定版 v1）

> 状态：**方案定稿，待批准后实施**（本轮不改任何代码）
> 基线：社区版 `coapis-agent` 开发树（版本号 1.2.15 线），企业版零改动继承
> 依据：生产环境实测 + 代码实证（数据见第 2 节）
> 用户四条拍板：①右侧整列彻底删 ②跨聊天汇总砍掉 ③气泡内本轮资源条保留 ④已下线产出卡删除

---

## 1. 四条拍板对应的落地边界

| # | 拍板 | 落地含义 | 边界（不做什么） |
|---|------|---------|----------------|
| 1 | 右侧整列彻底删 | 聊天页右侧那一整列（上半区"当前会话"+下半区"当前聊天"两块资源列表）从界面、样式、组件、数据钩子四个层面全部移除 | 不动左栏会话列表、不动抽屉、不动预览窗、不动气泡条 |
| 2 | 跨聊天汇总砍掉 | 前端不再存在"会话（跨多次聊天）"这个聚合视图：作用域状态机消失，抽屉标题恒为「当前聊天」，不再有任何 `scope=session` 请求 | **后端 `scope=session` 分支、台账聚合函数、357 行后端测试保留不动**（前端零调用，零风险，见 5.2） |
| 3 | 气泡内本轮资源条保留 | 每条 AI 回复下方的"本轮产出"文件条原样保留，含条上的「查看全部」入口 | 零改动 |
| 4 | 已下线产出卡删除 | 产出卡组件及其样式是死文件（全仓零引用），连同聊天页里两处指向它的过期注释一并清除 | 不动产出卡所用的那条数据流（它已被气泡条消费，见 4.3） |

一句话概括这次要做的：**把"同一批文件在界面上出现三次"收敛成一次——气泡条看本轮，左栏下拉看本会话，抽屉看全部。**

## 2. 现状实证（为什么可以整列删掉）

### 2.1 三处展示，一份数据

聊天页当前同一份资源台账出现在 3 处：

| 位置 | 组件 | 作用域 | 数据源 | 上限 |
|------|------|--------|--------|------|
| 右栏上半区 | `CoApisResourceStrip` | `session`（跨聊天） | `useScopedResources` | 40 |
| 右栏下半区 | `CoApisResourceStrip` | `chat`（本聊天） | `useScopedResources` → 同一模块级缓存 | 40 |
| 左栏会话行下拉 | `ChatSessionResourcesInline` | `chat` | `getChatResourcesShared`（同一缓存） | 40 |
| 气泡内本轮条 | `CoApisChatResourceBar` | 本轮 | 回答帧携带 | 本轮 |
| 抽屉（浮窗） | `CoApisResourceDrawer` | 跟随入口 | `ChatSessionResources` 表格 | 分页全量 |

实测结论（生产 v1.2.12 只读核查）：

- 右栏下半区与左栏下拉**同接口、同作用域、同缓存键**，一次生产抽样：右栏 40 条 / 左栏 6 条（同一会话聊天数差异所致），内容完全一致。
- 生产 153 次聊天分布在 150 个会话中，`session` 与 `chat` 两个作用域在 98% 的场景下命中同一批文件——**上半区与下半区展示的几乎就是同一份数据**。
- 右栏常驻固定 200px，把输入区挤窄，已导致输入框按钮被遮挡的线上缺陷（该缺陷当时是靠"窄屏隐藏右栏 + 输入框宽度地板"两处补丁绕过去的）。

### 2.2 右栏不提供任何独占能力

逐项核对右栏的功能，全部有替代入口：

| 右栏功能 | 右栏删除后的替代入口 |
|---------|-------------------|
| 看当前聊天的文件列表 | 左栏当前会话行下方展开列表（同为 40 条上限、同一缓存、同样预览/下载/删除） |
| 看跨聊天的文件列表 | 「我的空间」页面（跨会话文件总表，能力更全） |
| 打开完整台账抽屉 | 左栏「查看全部」+ 气泡条上的「查看全部」，两个入口都在 |
| 预览文件 | 预览窗（由文件芯片拉起，与右栏无关） |
| 窄屏折叠成图标条 | 整列消失，补丁一起下线，问题不复存在 |

**结论：右栏是纯粹的重复展示层，删除不减少任何功能，只减少噪音。**

### 2.3 相关体系规模（实证）

- 前端台账体系总量：14 文件 1867 行（组件 711 / 样式 441 / 逻辑 373 / 页面挂载 342）
- 后端台账：684 行实现 + 357 行测试
- 其中**已确认为死代码**：产出卡组件 267 行 + 样式 138 行（全仓零引用，唯一导出的类型也无人使用）

## 5. 明确不动清单（含理由）

### 5.1 界面层

| 保留项 | 理由 |
|--------|------|
| 左栏会话列表 + 当前会话行下方资源展开 | 会话级资源的唯一常驻入口，功能与右栏下半区完全等价且带完整操作 |
| 气泡内本轮资源条（拍板③） | 唯一"本轮产出"的即时反馈，与消息上下文绑定，右栏无法替代 |
| 资源台账抽屉（浮窗） | 完整表格：搜索、排序、分页、下载、删除；左栏与气泡条都指向它 |
| 预览抽屉 | 文件预览的唯一实现，与右栏无耦合 |
| 「我的空间」页面 | 跨会话文件总表的正式归属地，"跨聊天汇总"能力迁到此处（已有） |
| 输入框"+"菜单、知识库引用条 | 与右栏无耦合 |

### 5.2 后端与接口层（零改动）

| 项 | 位置 | 处置 |
|----|------|------|
| 资源列表接口的"跨聊天"分支 | `server/coapis/app/routers/chats.py` L1051 起 | **不动**。前端不再传入该作用域即为零调用；接口向后兼容 |
| 跨聊天聚合/计数函数 | `server/coapis/app/services/resource_ledger.py` | **不动** |
| 后端台账测试 | 357 行（含作用域用例 2 个文件） | **不动**，继续全绿，作为回归基线 |
| 前端接口封装中的作用域参数 | `client/src/api/modules/chat.ts` L237–250 | **不动**。默认"当前聊天"时不拼参数 → 请求 URL 与缓存键与今天完全一致 → 无缓存失效、无回归 |
| 台账写入（保存/上传/导出落库） | 后端链路 | **不动** |

**这样做的收益**：这次改动是**纯前端界面收敛**，数据层、接口契约、企业版数据流零触碰，风险面被压到最小。

### 5.3 企业版

企业版前端继承社区版聊天页，实测对企业版零引用右栏组件 → **企业版零代码改动**，只需随社区版重建镜像（版本号跟随社区版发布基线）。

| 用户想做的事 | 现在的路径 | 删后路径 | 是否变难 |

## 12. 回滚方案

- 全部改动走版本控制，回滚 = 一次 `git revert`（两笔提交，无数据迁移、无表结构变更、无缓存格式变更）。
