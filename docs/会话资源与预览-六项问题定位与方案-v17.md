## 1 · 左栏会话资源（问题 1）

**现状链路**
`ChatSessionSidebar/index.tsx:91-96` 给**每一行**会话都挂 `renderItemExtra` →
`ChatSessionDropdown/index.tsx:775-781`：

```ts
extra = props.renderItemExtra &&
  (expandedId ? session.id === expandedId
              : isCurrentSession(session))   // ← 收起后走这一支
```

**三条根因**

- **R1-a 收起等于没收起**：caret 收起 → `expandedId=null` → 条件回落到
  `isCurrentSession(session)`，当前会话那行的资源面板**立刻又渲染出来**，
  caret 也弹回展开态。用户看到的就是"点了没反应"。
- **R1-b 两把 id 尺子**：初值 `expandedId = props.currentBackendId`（后端 UUID，
  `:319` + `:335` effect），而 caret 回调写入的是 `session.id`（前端行 id）。
  对本地/临时会话（数字 id）`getBackendId()` 返回空 → `handleToggleExpand` 里
  `if (!backendId) return`（`:328`）直接吞掉点击；即使展开，
  `Inline.tsx:145` `if (!chatId) return null` → 面板永远是空的。
- **R1-c 视觉噪音**：`Inline` 的分组收起只收**条目**，组标题（引用 N / 产出 N）
  +「查看全部」恒渲染；左栏 260px 下每条会话底下都挂着这么一坨。

**方案（F1）**

1. 收起语义显式化：`expandedId` 初值改 `null`，渲染条件只认
   `session.id === expandedId`，**取消 `isCurrentSession` 回落**；默认展开位由
   聊天页传入（进入会话时展开当前会话），存 `sessionStorage` 记忆。
2. id 尺子统一：caret 一律传 `getBackendId(session)`，左栏形态只对**有后端 id 的
   会话**渲染 caret；无后端 id 的行不给 caret（不给必空的面板）。
3. 降噪：默认**只有当前会话行**挂 caret，其余行不挂资源入口（拍板 D1）。

**改动文件**：`ChatSessionDropdown/index.tsx`（约 25 行）、`ChatSessionSidebar/index.tsx`（约 5 行）。

## 3 · doc/xlsx 预览显示"不支持预览"（问题 3）

**后端能力早就在**：`app/services/file_service.py:102` 定义
`_OFFICE_PREVIEW_SUFFIXES`，`:737` 起把 docx/xlsx/pptx/odt/ods/odp
用 python-docx / openpyxl / python-pptx（markitdown 兜底）**转成 markdown**
以 `type:"text"` 吐回。

**前端主动关门**：`client/src/pages/Chat/workspaceLinks.ts:44-52` 的注释写着
F2 决策——"办公格式统一走下载下拉，不给看着像预览的东西"，于是
`PREVIEWABLE_SUFFIXES` 剔掉 office，`canInlinePreview` 也不认 → 抽屉收到点击后
被 `previewFile()`（`webPreview.ts:190`）判成 unsupported → 直接下载；抽屉里
打开的则显示"该文件不支持预览"（`CoApisPreviewDrawer.tsx:576,599`）。

**这就是"后端能预览、前端只给下载"的口径分裂**，与小蜜蜂看到的现象一字不差。

**方案（F3）**

1. `webPreview.ts`：新增 `OFFICE_EXT = {docx,xlsx,pptx,odt,ods,odp}`，
   `getPreviewKind` 返回 `"office"`；`canInlinePreview` 认它。
2. `workspaceLinks.ts:PREVIEWABLE_SUFFIXES` 同步补齐（两处必须同源，
   建议直接由 webPreview 导出，删掉前端第二份表）。
3. `CoApisPreviewDrawer.tsx`：`office` 走**已有的 markdown 渲染分支**
   （后端返回的就是 markdown 文本），头部加"转格式下载/原件下载"下拉；
   解析失败（依赖缺失/损坏）时显示后端给的提示文案 + 下载兜底。
4. 抽屉里的 markdown 渲染对 xlsx 的表格依赖 `remark-gfm`（已在依赖里）→ 无需新库。

**改动文件**：`webPreview.ts`、`workspaceLinks.ts`、`CoApisPreviewDrawer.tsx`、
4 语言 i18n 文案。约 90 行。

## 4 · 列表格式 / 更新时间 / 版本 / xlsx 缺失（问题 4）

### 4.1 xlsx 不进会话资源（**最硬的缺口**）

- `agents/context/reference_collector.py:48-52`：文件类只认
  `write_file / edit_file / send_file_to_user`（producer）与
  `read_file` 系（reference）；`:389` 起
  `else: return added` —— **`execute_shell_command`、Skill 脚本、MCP 工具产出的
  文件一律零登记**。xlsx 基本都由脚本（openpyxl/pandas）生成 → 天生不进台账。
- `foundation/file_ledger.py:667-772` 巡检 `reconcile()`：`rglob("*")` 扫全量文件，
  但**只 `s.add(FileRecord(...))`，从不调 `_sync_resource`** → 没有 `Resource` 行、
  没有 `chat` ref；而会话资源面板是**按 chat 的 ref join 查的**
  （`resource_ledger.py:1024-1055` → `chats.py:982`）→ 巡检补的文件在会话面板里
  **永远不出现**。而且它只在凌晨 3 点跑（`start_file_ledger_maintenance(hour=3)`）。

**方案（F4）**

- A：采集白名单扩口——把 `execute_shell_command` 纳入 producer 侧，**复用现成的
  `_normalize_file_path`（存在 + 落在本人工作区内）闸门**扫输出里的路径
  （`_extract_file_paths` 已实现，直接调用），上限 `MAX_PER_CALL` 保护。
- B：`reconcile()` 末尾对每条补扫到的文件调 `_sync_resource(source="reconcile")`，
  并按 owner 的**最近活跃会话**挂 `chat` ref（挂不上就只挂 owner，面板不显示，
  避免把历史文件硬塞进无关会话）。
- C：巡检触发加"会话结束后台补扫一次"（拍板 D7）。

### 4.2 更新时间不对（两种尺子混在一张表）

- `resource_ledger.py:254` 每次 re-register 都 `res.updated_at = now`
  —— **被引用一次，时间就跳一次**，不是文件修改时间。
- `app/routers/chats.py:1030-1041`：文件行用 `st.st_mtime` 覆盖，
  网页/兜底行用 `last_seen_at`，两者量纲不同；且台账侧历史字段是**naive UTC 字符串**，
  前端 `new Date(str)` 按本地解析 → 偏 8 小时。

**方案（F5）**：出参统一为 **epoch 毫秒**（文件=fs mtime，网页=首次引用时间），
前端一处 `formatEpoch()` 统一渲染；台账内部刷新只动 `last_seen_at`，
**`updated_at` 只跟随文件真实 mtime**（拍板 D5）。

### 4.3 版本管理

`resource_ledger.py:262-268`：

```python
if size and res.size_bytes and size != res.size_bytes:  # 只有大小变了才升版
    res.version += 1
```

- 同尺寸覆盖（模板/定长报表）**永不升版**；
- 首次登记时文件不存在 → `size_bytes=0` → 条件恒假 → **版本永远卡在 1**；
- 无 mtime/hash 参与判定，`upload_version()`（`file_ledger.py:379`）与它各算各的。

**方案（F6）**：升版判据改 `size 变化 || mtime 变化`（拍板 D6 选 A）；
台账与文件台账 `upload_version` 同一把尺子（mtime 单调）。

### 4.4 列表要有"文件列表的样子" + 预览/下载/删除

现状 L3 抽屉（`ChatSessionResources/index.tsx:202-360` 列定义、`:416` Table）已有
类型/名称/时间/大小/操作 五列，但**没有表头语义（无排序、无版本列）、没有删除、
没有预览按钮（名字点击即预览，不可发现）**。

**方案（F7）**

- 列：`名称（含扩展名）/ 类型 / 大小 / 版本 / 更新时间 / 状态 / 操作`，
  表头可排序（名称/大小/更新时间/版本）；操作列三枚图标按钮：
  **预览（eye）· 下载（↓）· 删除（🗑）**。
- 删除：后端已有 `DELETE /api/files/delete?path=&category=`
  （`app/routers/files.py:786`），但 `file_service.delete_file` 是**硬删
  （`file_service.py:770-772` unlink/rmtree）**，台账不会标 deleted →
  面板留下"missing"孤儿行。**新增软删**：移入 `.trash/<日期>/` +
  台账 `mark_status(deleted)`（拍板 D4），前端加二次确认。
- 前端 `api` 层补 `deleteWorkspaceFile()` 包装。

## 6 · 浮窗顶部无法拖拽（问题 6）

`FloatingWindow.tsx:444-449`：

```tsx
<div className={styles.header} onMouseDown={(e) => startDrag(e, "move")}>
  <div className={styles["head-title"]} data-nodrag>…   // ← flex:1 1 auto 铺满头部
  <div className={styles["head-extra"]} data-nodrag>…
```

`startDrag`（`:268-277`）对 `move` 模式先做
`closest("[data-nodrag],button,a,input,…") → return`。
`.head-title{flex:1 1 auto}`（`FloatingWindow.module.less:161-165`）把标题区撑满
整条头部剩余空间，且带 `data-nodrag` → **整条头部 100% 落在 nodrag 区**，
只剩按钮间 6px 缝隙能抓；光标也只在 `.freeform .header` 才 `cursor:move`（`:156`）。
另：`maximized / isMobile / isEmbedded()` 时 `startDrag` 直接 return（铺满态设计上不可拖）。

**方案（F9）**

1. 拖移热区从"标题文本"改成"头部空白条"：`head-title` **去掉 `data-nodrag`**，
   只给里面真正要交互的控件（标题里若有 input/下拉）单独标 `data-nodrag`。
2. 非铺满态整条 header `cursor: move`（`.freeform .header` 已有，扩到 header 本体），
   按钮/下拉/输入区 `cursor: default`。
3. 铺满态给提示：拖动手时 Toast/tooltip 提示"还原后可拖动"，并让"还原"按钮可发现。
4. 双击头部 = 铺满/还原（常见窗口习惯），与拖移不冲突（`dblclick` 与 drag 分离）。

**改动文件**：`FloatingWindow.tsx`（约 20 行）、`FloatingWindow.module.less`（约 12 行）。

## 需要小蜜蜂拍板

- **D1 左栏资源入口范围**：A 只有当前会话行给展开 caret（**推荐**，最干净）；B 每行都可展开（多 200 次请求/屏）。
- **D2 office 预览呈现**：A 抽屉内直接渲染后端 markdown（**推荐**）；B 表格类（xlsx）走"多 sheet 分页"增强（+0.5 人日）。
- **D3 xlsx 采集闸门**：A 扫 `execute_shell_command` 输出路径 + 工作区存在性闸门（**推荐**）；B 只信 write_file/send_file（现状，xlsx 继续缺失）。
- **D4 删除语义**：A 软删进 `.trash/<日期>/` + 台账标 deleted（**推荐**，可恢复）；B 直接硬删（现 `DELETE /api/files/delete` 行为）。
- **D5 更新时间口径**：A 文件=fs mtime、网页=首次引用，出参 epoch ms（**推荐**）；B 台账 `updated_at` 语义不变，前端只改格式化。
- **D6 升版判据**：A size 或 mtime 变化即升版（**推荐**，零额外 IO）；B 内容 hash（准确，大文件要读全文件）。
- **D7 巡检触发**：A 会话结束后台补扫一次 + 保留夜间全量（**推荐**）；B 只保留夜间 3 点。
