# 记忆系统整合设计方案（两层合一）

> 状态：待拍板 ｜ 日期：2026-10-06 ｜ 前置：G0 内存账本已提交（2ce17d9）＋ 已批《智能体能力提升》方案的时序记忆章节
> 原则：不丢弃任何一方成果 —— 已提交的 `memories` 账本**保留**，时序记忆**并入**，两者合成一条流水线。

---

## 1. 现状盘点（两套记忆的来历与差异）

| | 系统 A：记忆账本（已提交 2ce17d9） | 系统 B：时序记忆（已批方案，未动工） |
|---|---|---|
| 定位 | 蒸馏后的**长期策展记忆** | 对话事件的**原始流水** |
| 表 | `memories`（migration 0008，11 列） | `memory_timeline`（规划中） |
| 粒度 | 事实/偏好/决策，带 scope（user/agent/workspace） | 事件（纠正/决策/完成），带 session_id |
| 语义 | 去重合并（dedup_key UK），重要性加权 | append-only，时间有序，衰减归档 |
| 消费方 | 记忆注入（M3 路径）、统计、管理 | 审计追溯、近期回忆、晋升原料 |
| 生命周期 | 长期软删 | 90 天归档 |
| 状态 | 44/44 测试绿，工厂注入完备 | 仅存在于方案文档 |

**关键判断：两者不是竞争关系，是上下游关系。**
时序流水是"原料"，策展账本是"成品"，dream 是"加工厂"。原方案里 dream 只做"日记→MEMORY.md"一条线，整合后 dream 升级为统一编排入口，把两条线接起来。

另有一块**在途未提交**的 C1 残件：`compute_dream_outcome` 纯函数 + dream() 记账胶水 + `tests/test_dream_outcome.py`。它属于元记账（dream 跑得怎么样），已提交代码中 `record_outcome` 已预留承接位（`memories` 表 `category="dream"` 行，按 `(user_id, day)` upsert）。**整合方案直接吸收它，不再回滚。**

## 2. 目标架构

```
对话会话 (session JSON)
      │ ① 规则抽取（近24h变更，三类强信号：纠正/决策/完成）
      ▼
memory_timeline ──── 原始事件层（append-only，90天生命周期）
      │ ② 晋升（近7天 ∧ importance≥阈值 ∧ 未晋升过）
      ▼
memories ─────────── 策展层（去重合并，长期）
      ▲
      │ ③ 现有 MEMORY.md 蒸馏流（保持不变）
      │
      ├──▶ 记忆注入 M3（agent 上下文，现有路径不变）
      ├──▶ API /memory/timeline（审计/回忆）
      └──▶ API /memory/entries（调试/未来前端）

dream（_dream_callback）＝ 统一编排入口：
  Step1 dream()          日记→MEMORY.md（现有）
  Step2 record_outcome   本次 dream 结局记账（吸收在途C1）
  Step3 抽取→timeline    新
  Step4 晋升→memories    新
  Step5 timeline 衰减     新（超期降权/标记已晋升）
  每一步独立 try/except，任何一步失败不影响其余步骤与调度器
```

## 3. 数据模型

### 3.1 `memories` —— 保留不动
已提交 schema 完全保留（scope/user_id/agent_id/workspace_id/category/title/content/source/dedup_key UK/importance/时间戳/deleted_at）。
约定：`category="dream"` 为**系统保留类目**，专放 dream 结局元数据（`title=dream:{day}`，`content=status=…; reason=…; summary=…`），业务代码不得占用；`list_entries` 默认展示时可过滤该类目。

### 3.2 `memory_timeline` —— 新增
```sql
CREATE TABLE memory_timeline (
    id           BIGINT PRIMARY KEY AUTOINCREMENT,
    user_id      TEXT NOT NULL,
    agent_id     TEXT,
    session_id   TEXT,
    event_type   TEXT NOT NULL,          -- correction | decision | completion
    content      TEXT NOT NULL,
    importance   REAL NOT NULL DEFAULT 0.5,
    source_msg_ids TEXT,                 -- JSON 数组，溯源
    promoted_at  REAL,                   -- 晋升到 memories 的时间戳（NULL=未晋升）
    created_at   REAL NOT NULL,
    recorded_at  REAL NOT NULL
);
CREATE INDEX idx_timeline_user_time ON memory_timeline (user_id, created_at DESC);
CREATE INDEX idx_timeline_user_session ON memory_timeline (user_id, session_id);
```
比原方案多一列 `promoted_at`：晋升防重的唯一依据（替代原方案"consolidate 时猜测"）。

### 3.3 时序仓储 `MemoryTimelineRepository`（ABC，4 方法）
- `append(entry) -> int`
- `query(user_id, since=None, until=None, event_type=None, limit, offset) -> List`
- `recent(user_id, n=20) -> List`（含未晋升的高重要性事件）
- `maintain(now) -> dict`：① `age>30d ∧ importance<0.3` → 衰减归零；② 返回 `{archivable:[ids>, promoted:count}`，90 天物理删除交给 CleanupEngine（复用现有热温冷引擎，加一类 `memory_timeline` 规则）

## 6. 晋升策略（Step4，一期规则版）

候选条件（同时满足）：
1. `event_type ∈ {decision, correction, completion}`
2. `importance ≥ 0.6`
3. `now - created_at ≤ 7 天`
4. `promoted_at IS NULL`

命中后：`memories.add(scope="user", category=映射(event_type), title=摘要前缀, content=原文, source="timeline", importance=原值)`；`memories` 的 dedup_key 天然防二次撞车；成功后回写 `timeline.promoted_at`。
接口上预留 `Promoter` 协议位，二期可无缝替换为 LLM 精细抽取，不动表结构。

## 11. 最终落地决策（2026-10-06，D1–D5 按推荐执行后的工程裁定）

| # | 设计稿写法 | 落地实现 | 理由 |
|---|-----------|---------|------|
| F1 | `event_type` ∈ {correction, decision, completion} | 列名 `signal_type`，取值 {decision, preference, goal, conversation} | 提取启发式按语义价值分层比"三类强信号"更贴合实际；decision/preference/goal 可晋升，conversation 仅作流水展示 |
| F2 | 90 天物理删除交给 CleanupEngine | dream 第 5 步 `timeline.maintain(retention_days=90)` 直接硬删 | CleanupEngine 是文件生命周期引擎（JSON/gzip 热温冷归档），混入 DB 表删除增加耦合；dream 是天然夜间单写时机且幂等 |
| F3 | 表名 `memory_timeline` | `memory_timelines`（复数） | 与 `token_usage_details`、`point_transactions` 等既有表命名一致 |
| F4 | 晋升条件 importance≥0.6、≤7 天、未晋升 | 一致，另加单次上限 50 条（`limit`）防积压爆发 | 保护 memories 表增速 |
| F5 | `promoted_at` 为晋升防重唯一依据 | 一致（0011 迁移含该列） | — |

**验收口径不变**（§7）：构造含决策信号的会话 → 触发 dream → timeline 有事件、memories 有 `source="timeline"` 的晋升行、outcome 当天一行；三个端点 200；重复 dream 不重复晋升（`promoted_at` 生效）。
