## 0. 结论先行（四句话）

1. **技能触发不是"变弱"，是三条通道全部断裂**：关键词通道结构性失效、加权选择器完全未接线、大模型通道必然超时。中文消息 13 条实测只命中 2 条，且两条都是 `pdf`（唯一与中文输入同形的英文缩写）。
2. **根因是"从散文里正则抽触发词"这个设计本身**：技能描述整体被英文引号包裹，正则把**整段 200 字描述当成一个关键词**；作者用中文引号标注的真正触发词（"演示文稿""幻灯片""PPT"）**一个都抽不到**。17 个技能里 10 个关键词数为 0。
3. **这不是上下文优化的代价，而是可以兼得**：紧凑索引只花 264 字符，省掉了 6251 字符描述——省得对，但省掉了"什么时候该用"。给每个技能补一行触发词只需约 680 字符（是完整描述的 1/9），触发语义就回来了。**技能可见性与上下文预算不是零和。**

4. **技能默认加载的是英文版，不是中文版（v2 新增）**：同一容器同一智能体实测 `agent.language = 'zh'` 而 `skill pool language = 'en'`——**两条语言源互相矛盾**。技能池语言读的是工作区配置文件里的字段，该文件在开发/生产环境**都不存在**，代码回落到硬编码 `en`；界面语言只存在浏览器本地、**从不上报服务端**；而「语言设置」接口是**桩实现**（读取恒返回 zh、写入原样回显、零持久化）。17 个技能池条目盖章分布 `en:15 / zh:1 / 空:1`。**中文变体 17/17 齐备，切换零撰写成本，实测命中率 3/17 → 7/17、描述体积 −59%。**

## 2. 根因（六条，逐条代码实证）

### 2.1 触发词来源：从散文正则抽词，方向性失效

`react_agent.py:1774 _extract_keywords_from_description()` 用
`r'["\'"]([^"\'`]{2,})["\'`]'` 从 `description:` 里抽"引号短语"。

实测 `pptx-zh` 的描述：

```
straight-quote hits: ['当涉及到 .pptx 文件的任何操作时使用此技能……就使用此技能。']   ← 整段 200 字
curly-quote  hits : ['演示文稿', '幻灯片', 'PPT']                                    ← 一个都没被抽到
```

- 描述整体被**直双引号** `"..."` 包裹 → 正则把**整段描述**当成一个"引号短语"抽出 → 得到一个 200 字的"关键词"。
- 作者用**中文弯引号**「" "」标注的真正触发词，正则字符类里**没有** → 全部丢失。
- 函数注释自证了过度收缩：*"The previous token-splitting approach flooded the trigger set with generic verbs (创建/生成/转换/处理/表格/文档)"* —— 上一轮优化为了消灭误触发，把中文动词全砍了，**结果把召回也一起砍成 0**。这是典型的过度修剪。

### 2.2 匹配方向反了：要求"整段描述是用户消息的子串"

`intent_classifier.py:61 classify_intent_keywords()`：

```python
all_keywords = list(entry["trigger_keywords"])
summary = entry.get("description", "")
if summary:
    all_keywords.append(summary.lower())      # ← 整段摘要成为一个"关键词"
...
if kw_lower in msg_lower:                     # ← 方向：关键词 ⊂ 消息
```

对 10 个零触发词技能，`all_keywords` 里唯一的元素是**整段描述**。
`整段200字描述 in 用户一句话` —— 数学上恒为 False。

### 2.3 加权选择器 `SkillSelector` 完全未接线（死代码）

`skill_selector.py` 实现了完整的三级选择：Stage 0 场景优先 → Stage 1 加权关键词（技能名+关键词双权重）→ Stage 2 大模型兜底。

全仓库检索调用点：

```
react_agent.py:1398   self._skill_selector.build_index(skill_meta_list)     ← 只建索引
react_agent.py:1405   len(self._skill_selector.keyword_index)               ← 只打日志
```

**`select()` 零调用。** 建好的索引、双权重、场景优先、兜底分类，全部没有执行路径。
日志里那句「18 skills, 18 keywords」的 18 个关键词 = 18 个技能名 + 文件后缀（`.docx`→`docx` 与名字重复后净剩 18 个纯英文名）。

### 2.4 大模型通道必然超时 + 思考模型额度被吃满

- `intent_classifier.py:161 classify_intent_llm()` 内层 httpx `timeout=3.0`（配置 `llm_timeout_ms` 默认 3000）
- `react_agent.py:1879` 外层 `future.result(timeout=5.0)`
- 实测模型延迟：**6.24s / 7.71s / 7.56s** → **每次必超时**
- `max_tokens: 512` 发给思考型模型 → 实测 `finish_reason=length`，`content` 为空；
  虽有从 `reasoning` 里捞 JSON 的兜底，但思考链在 512 token 内还没输出 JSON 数组就被截断 → 返回 None

→ Phase 2 恒返回空。**Phase 1 空 + Phase 2 空 = 每轮零技能加载。**

### 2.5 中文变体从未被选中

`skills_manager.py:110 get_builtin_skill_language_preference()`：读配置 `builtin_skill_language`，缺省回落 UI 语言。容器实测返回 **`en`** → 池内全是英文变体 → 中文触发词设计（`-zh`）整体作废。

### 2.6 紧凑索引把"触发语义"压掉了（S1 的负外部性）

`react_agent.py:320 _SKILL_INDEX_COMPACT_ZH` 只渲染 `{names}`。
S1 优化把索引从 6515 字符压到 264 字符——**方向正确，压过头了**：
省掉的是"描述"，但同时把"何时该用"这个唯一能让模型自主决策的信息也省掉了。
`fixed_overhead.py` 的杠杆顺序里 `LEVER_SKILLS`（砍技能索引）排在**最后**、阈值 35%，
实测守卫**未触发** → 说明**当前固定开销占比低于 35%，索引这一项还有充足预算空间**。

## 3. 关键权衡：技能可见性 vs 上下文预算（不是零和）

| 索引形态 | 字符数 | 模型能否自主触发 |
|---|---|---|
| 完整描述（S1 之前） | 6515 | 勉强可以（描述冗长、英文、噪声大） |
| 裸名字（S1 现状） | 264 | **不能**（无任何语义） |
| **名字 + 触发词行（本方案）** | **≈680** | **能**（触发词即判据） |
| 名字 + 触发词 + 一句话（可选） | ≈1200 | 能（更稳） |

**每技能约 40 字符的触发词行，换来触发能力从 0 恢复到可用，成本是完整描述的 1/9。**
固定开销 ≈11137 字符、守卫阈值 35% 未触发 → 增加 416 字符（680−264）对预算无实质影响。

同时明确一条纪律，防止未来再次互相蚕食：
> **上下文压缩可以砍"描述正文"，不可以砍"触发语义"。**
> `LEVER_SKILLS` 降级时只允许把「名字+触发词+一句话」压成「名字+触发词」，
> **禁止压成裸名字**（裸名字索引 = 技能功能对模型不可用，等于功能消失）。

## 4. 方案设计

### 4.1 【核心】触发元数据契约：触发词写进 frontmatter，不再从散文抽

在 `SKILL.md` frontmatter 增加显式声明（**机制已存在，只是没人写**）：

```yaml
name: pptx
description: 任何涉及 .pptx 文件的操作……
trigger_keywords:            # ← 顶层，_get_skill_trigger_keywords 直接读它
  - 演示文稿
  - 幻灯片
  - ppt
  - pptx
  - 做个deck
trigger_patterns:            # ← 可选正则
  - "PPT|幻灯片|演示文稿"
trigger_examples:            # ← 供大模型兜底通道做 few-shot
  - 帮我做一个关于银发旅游的演示文稿
  - 把这份报告转成幻灯片
```

要点：
- **双语**：中文为主，英文为辅（`pptx`/`deck`/`slides`）。
- **禁止逗号入词**：现有 `deck,` `slides,` 这类带标点残片必须清洗。
- **禁止参数名当触发词**：`cdp_port`、`private_mode` 从触发词中移除（它们是工具参数，不是用户语言）。
- **禁止整句**：`the xlsx in my downloads` 这类必须拆词。
- `_extract_keywords_from_description` 降级为**兜底**，且：
  - 正则字符类补入中文弯引号 `“ ” 「 」 『 』`；
  - 抽出的短语**长度上限 12 字符**，超长直接丢弃（杜绝"整段描述当关键词"）；
  - 停用词表拦截通用动词（创建/生成/帮我/一下/这个/一个）。

**产出物**：`scripts/gen_skill_triggers.py` —— 扫描 17 个技能，生成触发词草案供人工确认；
`skills/*/SKILL.md` 全部补齐 `trigger_keywords`（17 个技能 × 8~15 词）。

### 4.2 匹配引擎重写（中文友好，零成本）

`classify_intent_keywords` 改造：

1. **方向修正**：只允许 `关键词 ⊂ 消息`，且关键词长度 ≤ 12；**移除"整段摘要当关键词"**。
2. **中文子串匹配天然可用**（中文无需分词，`"演示文稿" in "帮我做一个演示文稿"` = True）。
3. **英文词加词边界**：`ppt` 不应命中 `pptx` 之外的上下文时误伤 → 用 `\b` 边界；
   文件后缀（`.pptx`）单独走后缀匹配通道。
4. **命中打分**：命中词数 × 词长权重，取 Top-3（现有 `max_skills=3` 保留）。
5. **场景加权**：命中技能若在当前场景的 `skill_ids` 白名单内，权重 ×2（复用 `SkillSelector` 已有的场景优先逻辑）。

### 4.3 索引分层（三层按需，与「分层暴露」设计规范一致）

| 层 | 内容 | 字符 | 何时给模型 |
|---|---|---|---|
| L1 常驻 | 名字 + 触发词行 | ≈680 | 每轮（默认） |
| L2 命中 | 命中技能的一句话说明 + 关键参数 | ≈200/技能 | 关键词命中时注入 |
| L3 全文 | 完整 SKILL.md | 2~6K/技能 | 模型调用 `skill_manager(action="info")` |

L1 渲染示例（新增 `_SKILL_INDEX_TRIGGER_ZH`）：

```
可用技能（名字｜触发线索）：
pptx｜演示文稿 幻灯片 PPT .pptx
docx｜Word 文档 报告 合同 .docx
xlsx｜表格 Excel 报表 .xlsx .csv
cron｜定时 每天 每周 提醒 计划
news｜新闻 资讯 热点 今天
...
需要完整用法时调用 skill_manager(action="info", name="技能名")
```

配置开关：`running.skill_index_mode = "trigger" | "compact" | "full"`，默认 `trigger`；
`skill_index_compact=True` 旧语义映射为 `compact`，保持向后兼容。

### 4.4 接线 `SkillSelector`（消灭死代码）

`_load_on_demand_skills` 改为调用 `self._skill_selector.select(...)`，
把 Stage 0（场景优先）/ Stage 1（加权关键词）/ Stage 2（大模型兜底）真正接入执行路径；
`classify_intent_keywords` 作为 Stage 1 的实现保留。
**若判定不接线，则删除 `skill_selector.py` 的 Stage 0/2 与双权重逻辑**——不留死代码。

### 4.5 大模型兜底通道改造（不再阻塞当轮）

三选一，推荐 A+B 组合：

- **A. 参数修正**：`llm_timeout_ms` 3000 → **12000**；外层 5s → 13s；
  `max_tokens` 512 → **1500**，并对思考型模型显式 `"thinking": {"type": "disabled"}`；
  解析失败时保留现有从 `reasoning` 捞 JSON 的兜底。
- **B. 异步旁路**：兜底分类**不阻塞当轮**——后台发起，结果写入会话缓存，
  **下一轮生效**（技能加载本就是"下一轮生效"语义，见 `_register_skill_summary` 注释，天然契合）。
- **C. 直接下线该通道**：4.1+4.2+4.3 生效后，确定性通道已覆盖绝大多数场景，
  大模型兜底收益极低、成本极高（每轮多一次 7 秒 LLM 调用）。

> 建议：**先做 A（1 行配置）观察，若命中率仍低再做 B；C 作为最终简化选项。**

### 4.6 语言变体选择修复（**v2 已扩写为第 5 章专项，此处只留摘要**）

- 语言偏好解析链改为四级：**显式覆盖 → 智能体语言（真相源，当前 `zh`）→ 部署级环境变量 → 兜底 `zh`**（当前兜底是硬编码 `en`，对中文产品是错的）。
- 破除「条目盖章粘死」：优先级改为 **显式覆盖 > 全局偏好 > 条目盖章**，让改偏好能作用于已建池。
- 新增**批量重烘焙**操作：按新偏好重选变体、重写盖章、重建池内容。
- 「语言设置」接口从桩实现改为真读写（写工作区配置文件并生效）。
- ~~补齐缺失的中文变体~~ → **v2 核查推翻：中文变体 17/17 齐备，零撰写成本**（见 5.4）。

### 4.7 与上下文/工具压缩的协同（统一"名字+线索，详情按需"范式）

把三处压缩统一到同一范式，避免各自为政互相蚕食：

| 对象 | 常驻层 | 按需层 | 现状 | 目标 |
|---|---|---|---|---|
| 技能索引 | 名字+触发词 | `skill_manager(info)` | 裸名字 | **名字+触发词** |
| 工具 schema | 名字+一句用途 | 参数详情按需 | 6729 字符全量 | 常驻压到 ≈2500，参数按需 |
| 记忆/历史 | 摘要+索引 | `recall_history` | 已实现 | 保持 |

预算侧（`context_budget.py` / `fixed_overhead.py`）：
- 给技能索引设**独立预算线**（建议 1200 字符上限），并在 `LEVER_SKILLS` 降级链里
  设**下限保护**：`full → trigger`，**禁止 `trigger → compact(裸名字)`**。

## 5. 语言适配专项（v2 新增 · 已实测验证）

### 5.1 现象与结论

**用户观察成立：技能确实默认加载英文版。** 中文环境下这是三重损失——命中率、token、一致性同时受损。

### 5.2 三条语言源与实测（同容器同智能体）

| # | 语言源 | 位置 | 实测值 | 谁在用 |
|---|---|---|---|---|
| ① | **智能体语言** | 智能体配置文件的顶层 `language` 字段 | **`zh`** ✅ | 技能索引模板语言（`react_agent.py:1469`）、工具描述数据包（启动日志 `Applied 28 tool descriptions from data pack (lang=zh)`）、主动回复 |
| ② | **技能池语言** | 工作区配置文件 `settings.json` 的 `builtin_skill_language` / `language` | **文件不存在 → 回落硬编码 `en`** ❌ | **技能变体选择（选 `-en` 还是 `-zh`）** |
| ③ | **界面语言** | 浏览器本地存储 `language`，默认 `zh` | `zh` | 仅前端文案，**从不上报服务端** |

> 实测原话（开发容器 + 生产容器各跑一遍）：
> `agent.language = 'zh'`
> `skill pool language = 'en'`
> 生产容器 17 个技能逐一解析：**全部 → en**。

**关键判断**：①②是两套互不相通的读取路径。①已经正确是中文并被索引与工具描述使用；②独立读文件、文件缺失、兜底写死 `en`。**所以「界面中文、技能英文」不是巧合，是两条语言源没有打通。**

### 5.3 四条根因（逐条实证）

| # | 根因 | 证据 |
|---|---|---|
| **L1** | 技能池语言偏好读工作区配置文件，**该文件在开发/生产环境均不存在** → 代码回落硬编码 `en` | 两环境 `ls settings.json` 均「不存在」；偏好实测返回 `'en'` |
| **L2** | 「语言设置」接口是**桩实现**：读取恒返回硬编码 `zh`，写入原样回显请求体，**零持久化** | 路由源码：读取函数体只有 `return {"language": "zh"}`；写入函数体只有 `return {"language": payload.get(...)}`；全仓 `grep settings.json` 只有读、**无任何写入方** |
| **L3** | **池条目语言「一次盖章、永久粘死」**：条目里已记录的语言字段优先级**高于**全局偏好，改偏好对已建池**永不生效** | 解析函数源码：条目已记录 → 直接返回，不看偏好。实测：写入偏好 `zh` 并重启后，池分布**仍是 17×en**，纹丝不动 |
| **L4** | 唯一有效入口是**逐个技能**手动切换接口，**没有「按偏好批量重烘焙」的操作** | 单技能切换接口存在且有效（实测 `pdf` 切 zh 后描述立刻变中文）；批量入口全仓无 |

### 5.4 中文变体齐备性核查（**修正 v1 判断**）

v1 曾写「补齐缺失的中文变体（当前 browser_use 只有 -en）」——**该判断错误，本轮核查推翻**：

| 项 | 实测 |
|---|---|
| 打包内置技能目录数 | 34 |
| `-en` 变体 | **17** |
| `-zh` 变体 | **17** |
| 缺中文变体 | **0 个**（含 `browser_use-zh`、`browser_cdp-zh` 均存在） |
| 注册表可用语言 | 17 个技能**全部**为 `['en','zh']` |

→ **E 波次性质改变：不需要撰写任何中文内容，只需把「选择逻辑」修好。** 工作量从「写 17 份中文」降为「修语言解析链 + 批量重烘焙」。

### 5.5 语言切换的实测收益（A/B 对照，17 条中文消息）

| 指标 | 英文池 | 中文池 | 变化 |
|---|---|---|---|
| 技能描述总长 | 6171 字符 | **2527 字符** | **−59%**（每条均长 363 → 148） |
| 描述中的中文字符 | **0** | 1382 | 中文用户可见内容从「零中文」变为有 |
| 关键词通道命中（17 条中文消息） | 3/17 | **7/17** | **+133%** |
| 命中样例 | 仅 pdf / xlsx 等与中文同形的缩写 | 新增 `docx`（Word文档）、`pptx`（幻灯片）、`news`（新闻）、`cron`（日历） | 从「只能靠缩写」到「语义可命中」 |

> 说明：关键词通道命中绝对值仍低（7/17），因为该通道只抽引号短语与文件后缀——**这正是要靠 A 波次显式触发词修复的部分**。语言适配与触发词修复是**相乘关系**：中文触发词只有配在中文描述上才自然，两者合起来才是完整解。

### 5.6 设计：单一真相源 + 四级解析链

**唯一真相源 = 智能体语言（①）**。理由：它已存在、已是 `zh`、已被索引与工具描述使用，是系统里唯一「正确且生效」的语言源。

```
技能池语言偏好解析链（自上而下，命中即止）
  1. 工作区配置文件里的显式覆盖字段   ← 保留现有能力（运维强制）
  2. 智能体配置的语言字段（当前 zh）  ← 【新增】接入唯一真相源
  3. 部署级环境变量                    ← 【新增】容器可注入，便于镜像/编排层控制
  4. 兜底默认                        ← 由硬编码 en 改为 zh（产品定位中文优先）
```

**配套三件**：

| 项 | 内容 |
|---|---|
| **破粘性** | 解析优先级调整为：**显式覆盖 > 全局偏好 > 条目盖章**。让「改偏好」能真正作用于已建池，不再一次定终身 |
| **批量重烘焙** | 新增一次性操作：按新偏好把全部内置技能条目重选变体、重写盖章、重建池内容。幂等、可重复执行、带前后分布日志 |
| **接口落地** | 「语言设置」接口从桩改为真读写：写入工作区配置文件并生效；读取真读文件。前端切换语言时调用，实现「界面语言 = 技能语言」一次联动 |

### 5.7 已完成的实测验证（开发环境，非破坏、可逆）

| 步骤 | 结果 |
|---|---|
| 写入语言偏好文件（`builtin_skill_language: zh`） | 偏好立即变 `zh`，17 个技能解析全部 → zh ✅ |
| 重启服务 | 池盖章**未变**（17×en）→ **实证 L3 粘性缺陷** ✅ |
| 逐个技能调用切换接口 ×17 | **17/17 成功**，池分布变为 **`zh:17`** ✅ |
| 抽查技能内容 | 描述与正文均为中文（如 pdf 返回「需要处理 PDF 文件时使用」） ✅ |

> 开发环境（4110）现已处于**全中文技能池**状态；生产环境（4890）未动，仍是 en 池，等 E 波次正式落地。

### 5.8 语言维度风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 中文描述更短导致信息量下降 | 中文每条 148 字符 vs 英文 363 | 中文描述已含触发场景列举；A 波次显式触发词字段独立于描述长度，不受影响 |
| 用户已习惯英文技能名 | 技能名（`pdf`/`pptx`）是标识符，不翻译 | **只切描述与正文，名字保持英文**——与 D3 拍板（名字+触发词索引）天然一致 |
| 盖章粘死导致改了不生效 | L3 | 破粘性 + 批量重烘焙为 E 波次必做项，验收强制检查 |
| 多用户部署语言不一致 | 池是全局的，语言偏好也是全局 | 本期按**部署级**统一（与现状一致）；智能体级语言差异化列为后续议题，不在本期 |
