# CoApis底座外部系统集成与技术交互方案 v2.1（最终优化版）

## 1. 方案概述与核心理念

CoApis作为企业级AI智能体底座，其核心使命是**"提质增效"**而非盲目追求自动化替代。在真实的企业业务环境中，大量外部系统为第三方SaaS、老旧ERP或闭源legacy系统，无法支持深度代码对接（如`postMessage`通信或自定义数据回执API）。

本方案基于**"AI辅助决策"**与**"容错降级机制"**的核心理念，将系统集成分为三大类接入场景，并明确了各类场景下的**数据交互规范**、**动作/业务闭环策略**以及**故障降级路径**。

---

## 2. 外部系统接入分类与技术可行性矩阵

根据外部系统的开放程度与代码修改权限，CoApis的集成方案划分为以下三类：

| 类别 | 系统特征 | 典型场景 | 数据输入给AI的方案 | AI动作/业务闭环方案 |
| :--- | :--- | :--- | :--- | :--- |
| **A类：完全开放** | 自研或深度合作，支持前后端代码修改与API定制。 | 内部OA、ERP、BI系统深度集成。 | URL参数初始化 + `postMessage`协议 + MCP工具注册中心/API网关。 | C2A Action (`api_call/form_submit`) 触发外部回执API `/api/ai/action-receipt`。 |
| **B类：半开放/Web SaaS** | 支持前端嵌入（Iframe/JS SDK），但无后端自定义接口权限。 | OA看板、第三方CRM、项目管理平台。 | Iframe URL参数初始化 + Browser Extension DOM捕获。 | UI级交互：复制到剪贴板、导出文件（CSV/PDF）。用户在原生UI中手动闭环。 |
| **C类：完全封闭/Legacy** | 无API、非Web系统或闭源SaaS，零代码侵入权限。 | 传统桌面软件、老旧ERP、不支持修改的第三方业务系统。 | RPA通道读取页面DOM快照 / DB直连拉取数据库数据。 | RPA UI自动化执行（模拟点击/填写）或 DB直连写入。无HTTP回执请求。 |

## 3. 数据交互方案：上下文输入与快照拉取

### 3.1 `/chat/embedded` URL 参数优化设计
根据"非敏感短小参数直接带在URL中，外部系统API地址Base64编码后传递"的原则，正确的嵌入 URL 示例如下：

```text
http://localhost:4308/chat/embedded?token={认证令牌}&scene_id={场景ID}&context_api=aHR0cHM6Ly9leHRlcm5hbC1zeXN0ZW0uY29tL2FwaS9jb2FwaXMvY29udGV4dC1zbmFwc2hvdA==&initial_prompt=请分析当前列表的趋势并给出建议
```

#### 参数详细说明：
| 参数名 | 说明 | 是否必须/特征 |
| :--- | :--- | :--- |
| `token` | CoApis 认证令牌，用于身份验证与会话恢复。 | **必须**。安全凭证。 |
| `scene_id` | 场景/业务实体 ID（如列表、看板、项目等），用于标识当前业务上下文归属。 | **必须**。短字符串。 |
| `context_api` | **外部获取数据的 API 地址的 Base64 编码值**。CoApis 后端解码此参数后，直接调用该外部系统 API 获取只读的业务数据快照（Snapshot）。 | **按需传递**。用于解决复杂/庞大业务上下文的数据拉取问题。 |
| `initial_prompt` | 自动发起聊天的"用户问题"或初始提示词（如："请分析当前列表的趋势并给出建议"）。 | **按需传递**。非敏感、短小，无 URL 超长风险。 |

*(注：由于设计简化，`intent` 参数不是必须的。CoApis AI 会根据 `initial_prompt` 的语义以及从 `context_api` 拉取到的数据结构，自动推断并执行相应的分析或审查意图。)*

### 3.2 `context_api`（外部获取数据的 API）机制设计
您提出的"直接给外部获取数据的 api（可以 base64 编码）"的设计非常合理且灵活：
1. **Base64 编码的必要性**：外部系统的上下文数据拉取 API 地址通常包含域名、路径以及可能的查询参数。通过 Base64 编码，可以确保该 API 地址在 URL 参数中安全、完整且无歧义地传递，避免特殊字符导致解析混乱或触发 Web 服务器/网关的转义问题。
2. **CoApis 后端的拉取流程**：
   - Co/apis 后端接收到 `/chat/embedded` 请求时，解析并 Base64 解码 `context_api` 参数，得到外部系统的数据获取 API 地址。
   - Coapis 使用预配置的内部服务凭证（或根据场景要求的鉴权方式），向该外部 API 发起 HTTP GET/POST 请求。
   - 外部系统返回符合其自身业务模型的只读数据快照（Snapshot JSON）。Co/apis 解析该快照，并将其作为 LLM 的上下文输入，触发 AI 的分析或辅助生成。

### 3.3 RPA/DOM快照捕获与DB直连（适用于C类封闭系统）
- **RPA通道**：CoApis Agent通过内置的 **Browser Control Tool (Playwright/Puppeteer风格)**，直接读取目标外部系统页面的DOM结构、表格数据或屏幕截图作为上下文快照输入给LLM。
- **DB直连通道**：对于无对外API但有数据库访问权限的内部系统，通过安全审计的只读/写权限连接器，直接向目标数据库表查询业务数据作为AI上下文。

## 4. 动作交互方案：辅助决策与业务闭环（无需强制回执）

根据"AI是辅助不是替代"的原则，C2A (Chat-to-Action) 协议的 `intent` 分类和卡片渲染逻辑需明确区分**只读分析类**、**判别审查类**与**辅助生成类**。

### 4.1 分析与洞察类（Analysis & Insight）
- **AI角色**：超级分析师，提取关键信息并生成趋势报告或高亮异常点。
- **C2A卡片类型**：`data_table`（数据表格）、`text_reply`（文本总结）。
- **动作交互/闭环方式**：**无强制回执**。提供"复制分析摘要"、"导出为Markdown/PDF文档"按钮，由用户自行在外部系统中做决策。

### 4.2 判别与审查类（Judgment & Review）
- **AI角色**：智能审核员，基于规则或经验对输入内容进行判别，给出结论及风险点提示。
- **C2A卡片类型**：`alert_card`（警告卡片）、`checklist_card`（审查清单）。
- **动作交互/闭环方式 (Human-in-the-loop)**：用户在外部系统的原生UI中手动点击"接受建议"、"驳回"或"标记为已处理"。数据回执由外围系统原生的业务流完成，Coapis不触发后端API回调。

### 4.3 辅助生成类（Assistance & Drafting）
- **AI角色**：智能秘书，根据上下文快速生成结构化的初稿（会议纪要、邮件起草）。
- **动作交互/闭环方式**：提供"复制到剪贴板"、"导出为Word/Excel"按钮。用户在外部系统表单中粘贴或上传，AI不直接触发系统的提交API。

### 4.4 自动化执行类（仅适用于A类开放系统）
- **C2A Action意图**：`intent: 'api_call'` 或 `intent: 'form_submit'`。
- **动作交互/闭环方式**：通过外部业务系统提供的标准数据回执接口（如 `POST /{external_system_base_url}/api/ai/action-receipt`），将AI生成的结构化结果（`suggested_fields`, `recommendations`）传回，完成自动回填或流程触发。

## 5. 容错与降级机制设计（Fault Tolerance & Graceful Degradation）

在真实的外部系统集成中，系统必须具备"容错与降级"能力，确保AI辅助体验的连续性：

### 5.1 上下文快照缺失或解析失败的降级策略
- **场景约束**：外部系统传递 `context_api` 时因网络问题或API不可用导致无法拉取业务数据快照。
- **容错/降级方案**：Coapis前端不显示"加载失败"的空白页，而是切换到"通用对话模式"，并提供结构化表单或文本框："请提供您想要分析的数据或上下文（如复制粘贴表格内容、上传文件）"。

### 5.2 LLM生成分析结果失败或"幻觉"的容错机制
- **场景约束**：LLM无法生成符合C2A协议规范的 `data_table`，或输出存在不确定性。
- **容错/降级方案**：
  - **格式回退（Fallback to Text）**：自动降级为纯文本的Markdown总结回复，确保用户获得文字层面的分析结果。
  - **置信度提示与人工复核**：在审查类场景中，若AI判别置信度较低，C2A卡片应明确标注"建议人工复核"，而非直接给出绝对结论或触发自动操作。

### 5.3 RPA/UI自动化通道执行失败的降级策略
- **场景约束**：Coapis尝试通过RPA通道读取数据或模拟填写表单时，因页面DOM结构变化而失败。
- **容错/降级方案**：系统通过C2A文本回复告知用户："自动读取/填写操作未成功完成"。同时提供替代方案，如"导出当前分析结果为CSV文件"，供用户在外部系统中手动导入。

### 5.4 MCP工具调用或API网关超时的容错机制
- **场景约束**：AI通过MCP Server调用外部系统REST/GraphQL API时遇到超时或5xx错误。
- **容错/降级方案**：部分结果返回与警告提示，明确说明哪些数据已成功获取、哪些因网络原因未能拉取，并提供重新触发的按钮（Retry）。

## 6. 统一认证与身份映射体系 (SSO/Auth Integration)

无论外部系统开放程度如何，首先需通过统一的认证机制解决用户身份映射和权限同步问题：
- **OAuth2 / OIDC / SAML协议对接**：支持企业微信、钉钉、飞书等内部移动端的认证协议集成。
- **LDAP/AD域同步能力**：实现外部系统用户角色与权限的自动映射到CoApis中。
- **Client Credentials机制**：适用于机器对机器（M2M）的外部系统API调用场景，提供统一的鉴权令牌。
