# 记忆台账桥接与作用域/语义增强实施方案

> 状态：批次 1（桥接）已实现并测试通过（22/22）；批次 2/3 待排期。
> 依据：对 coapis-agent 记忆体系的完整代码审计（"只写不读"负结论复核）。

## 1. 现状审计结论

1. **新台账"只写不读"**：memory_timelines 表由 dream 流水线/cron 持续写入，
   但没有任何环节把台账内容注入聊天上下文——智能体不知道台账的存在。
2. **作用域严格单人**：memories 表有 scope ∈ {user, agent, workspace} 三档，
   但 workspace 作用域定义了却无人写入/消费，等于官方给组织协作留的空钩子。
3. **语义匹配是朴素词法重叠**：memory_search 底层是文件级语义+关键词；
   DB 台账侧完全没有检索通道（list_entries 仅有 ILIKE 子串）。
4. **已有桥接（勿混淆）**：`foundation/memory_injector.py` 注入的是
   MEMORY.md 风格的**文件记忆**，不是时间线台账。本方案补的是后者。

## 2. 总体设计

三条增强线，全部落在**社区版仓库**（企业版免费获得，企业版无知识库部分不受影响）：

- **桥接（批次 1）**：台账 → 上下文的读写通路
- **作用域（批次 2）**：workspace 作用域启用（组织共享记忆）
- **语义（批次 3）**：hash 弱语义常开的相似度升级

## 3. 批次 1：桥接（本次已实现）

### (a) 被动摘要注入
- 新模块 `foundation/timeline_digest.py`：`build_timeline_digest(user_id, hours=72, limit=30, max_chars=600)`
  把用户近 72h 的时间线信号渲染为紧凑文本块（决策/事实/待办/纠偏标签 + ★高重要性）。
- `agents/core.py::_build_full_system_prompt` 在 [MEMORY] 块之后追加该块。
  只读、异常静默降级为空串，绝不影响提示词主体。
- user_id 采用 username 字符串命名空间（与 crons/manager.py 写入侧一致，
  chats.py 中 `payload.get("user_id", username)` 证实同命名空间）。

### (b) memory_search 双轨
- `agents/memory/reme_light_memory_manager.py::memory_search`：
  文件检索结果为主，DB 台账（近 90 天时间线 + list_entries(q) 记忆条目）
  以关键词重叠打分（英文词元 + 中文二元组，importance≥8 加 0.1）追加为
  "[记忆台账补充（数据库）]" 段落。
- 台账查询经 `asyncio.to_thread` 走工作线程；任何异常降级为纯文件结果。
- 注：本版为"分段追加"式融合（ToolResponse 结构不透明，不做侵入式 RRF 交织）；
  真正的 RRF 秩融合留给批次 3 与语义升级一起做。

### 测试
- `tests/test_timeline_bridge.py`：22 条断言全绿（摘要 12 + 双轨 10）。
